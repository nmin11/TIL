# 기술 스택을 일본 시장에 맞게 설계하는 방법

## 기술 스택은 '많이 아는 것'보다 '채용되는 조합'이 중요하다

- 현장에서 바로 쓸 수 있는 조합이 중요
- 최신 기술만 좇는 경우는 좋지 않게 보일 수 있음
- 기술 스택을 설계할 때 지원할 직무 유형과 기업 유형을 정해야 함

## 일본 채용 공고에서 자주 보이는 핵심 기술

- 백엔드: Java, Spring Boot, PHP, Laravel, Python, Ruby on Rails, Go
- 프론트엔드: JavaScript, TypeScript, React, Vue.js
- 클라우드: AWS가 압도적
  - EC2, S3, RDS, IAM, VPC, Lambda, CloudWatch
  - Docker, Linux, CI/CD 경험도 있으면 유리
- 데이터 & AI: Python, SQL, Pandas, TensorFlow, PyTorch, BigQuery, Snowflake, Airflow
- 보안: 네트워크, Linux, 클라우드 보안, 취약점 진단, 로그 분석, SIEM, IAM 지식

## 직무별 우선순위를 명확히 정하라

- 백엔드
  - 첫번째는 언어와 프레임워크
  - 다음은 SQL, REST API 설계, 인증·인가, 테스트 코드, Git
  - 가능하다면 Docker와 AWS 배포 경험까지
- 프론트엔드
  - JavaScript와 TypeScript가 기본
  - React 혹은 Vue.js 실전 프로젝트
  - 로그인, 권한 처리, 검색, 필터링, 페이지네이션, 에러 처리
- 클라우드
  - 먼저 Linux와 네트워크 기초부터
  - AWS 주요 서비스들, Docker, Terraform, CI/CD
- 데이터 & AI
  - Python과 SQL을 절대적인 기본기로
  - 머신러닝 공부, 데이터 수집, 전처리, 파이프라인, 시각화, 모델 배포
- 모바일
  - Android는 Kotlin, iOS는 Swift가 기본
  - Flutter, React Native 같은 크로스플랫폼 기술도 활용됨
  - 푸시 알림, API 연동, 로컬 저장소, 앱 배포, 성능 개선 경험

## 기업 유형에 따라 기술 전략을 다르게 가져가라

- SI 기업
  - 안정성과 범용성을 중시
  - Java, Spring, Oracle, MySQL, Linux, Git 등 전통적이고 검증된 기술 선호
  - 문서화, 테스트, 유지보수 능력도 중요하게 평가됨
- 자체 서비스 기업
  - 제품 개선 속도와 사용자 경험 중시
  - 백엔드: Go, Ruby on Rails, Python, Node.js
  - 프론트엔드: React, TypeScript
  - 데이터 기반 의사결정, A/B 테스트, 로그 분석, 클라우드 운영 경험
- 스타트업
  - 넓은 역할을 감당할 수 있는 사람 선호
- 외국계 기업
  - 클라우드, 알고리즘, 시스템 설계 역량을 더 보는 느낌
  - 기술 면접의 난도가 높고, 구체적인 경험과 성과 필요

## 초보자는 'T자형 스택'으로 설계해야 한다

- 주력 직무를 깊게 배우고, 협업에 필요한 주변 지식을 익히는 방식
- 장점: 면접에서 설명을 명확하게 할 수 있음
- 기술 스택은 이력서, 직무경력서, 포트폴리오, 면접 답변이 모두 같은 방향을 가리켜야 함
